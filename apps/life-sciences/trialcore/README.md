# TrialCore

> Enterprise multi-site clinical trial management — run every trial, every site, in one place.
> **Live:** [trialcore.supero.live](https://trialcore.supero.live) · **Industry:** life-sciences

> **⚠️ Regulated data.** This is a reference app, **not a HIPAA-certified system**, and it ships with no BAA. Running it as-is sends the data you enter to the hosted platform at `api.supero.dev`. Do not put real PHI in it without an enterprise agreement and BAA — see [SECURITY.md](../../../SECURITY.md).

Part of [Supero Apps](../../../README.md) — clone it onto a domain you own and run it. The
app source here is MIT.

## Run it

```bash
cp .env.example .env      # set SUPERO_DOMAIN (any free name) + SUPERO_PASSWORD
./run.sh                  # Linux/macOS   ·   run.bat on Windows
```

Opens at **http://localhost:5668**. You do **not** need a Supero account — `run.sh`
registers the domain you name in `.env`. Docker works too: `docker compose up`.

> Set `SUPERO_PASSWORD` in `.env` — the app refuses to start without it (no default).

## What's inside

- **Entities** (`schemas.py`): `Trial`, `Site`, `Participant`, `Visit`, `AdverseEvent`, `TrialDocument`
- **Services** (`config.py`): `email`, `slack`, `ai`, `workflows`
- **Access rules** (`setup.py`): role-based, enforced server-side
- **Custom UI**: `ui/app.js` — the one file you edit; everything else in `ui/` is
  regenerated by the SDK on `run.sh`

## Make it yours

- **Data model** → edit `schemas.py`, then `./run.sh --reset`
- **Screens** → edit `ui/app.js`, refresh (no build step)
- **Services / seed data / roles** → `config.py` and `setup.py`
- **Branding & layout** → see `CUSTOMIZATION.md`
- **With an AI assistant** → `CLAUDE.md` (also `.cursorrules` / `.windsurfrules`)
